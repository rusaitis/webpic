## M2 — Volume + perf gate
Goal: single-scalar volume raymarcher hitting the perf gate; time-series scrub.

Single-pass volume raymarcher (TSL `NodeMaterial` + `wgslFn`, render-local — not a shared kernel); analytic ray-box, early-α (≥0.98) termination. `render/raymarchScene.ts` (TSL `Loop` + `wgslFn` `hitBox` + front-to-back composite); `rayBox.ts` TS twin + Node tests. Slice stays app default until the M2.2 UI toggle.
- [x] 2. **`ui/` scaffold** — hideable shell panels + dependency-free `Pane`/`Folder`/`Binding` controls facade (slider/select/checkbox/text, ported from `magviz/src/ui/controls`, **no `tweakpane`**) on a callbacks-out / `set()`-in contract with `ownerDocument` DI. `ui` dispatches typed store intents only — never imports `render` (DAG-enforced); embed renders without `@webpic/ui`. `installUi()` mounts a themed docked shell + field selector (`selectField` intent) + `layers`/`diagnostics` placeholders + `toggleUi` shortcut. (Full `RangeControl` → M2.3.)
- [x] 3. Transfer-function texture (256×1 `rgba16float`) + window/level via **owned `RangeControl`** (ported from magviz: full linear/log/symlog/interval + `rangeMath`) — its `{center,width}` output is the canonical range form M2.5b's `ColormapBinding` stores (no separate `min/max`). `render/transferFunction.ts` bakes the colormap LUT (RGB; alpha reserved for the M2.7 opacity TF); window/level become `uWindowCenter`/`uWindowWidth` uniforms with an in-place `setWindowLevel` so dragging never re-uploads the volume. The **Layers** placeholder becomes a real window/level panel (M2.5b adds colormap + scale pick).
- [x] 4a. **Render loop + store-owned camera pose** — lift the camera out of the scene factories into `render/camera.ts` (`applyPose` + `DEFAULT_POSE`); pose lives in the store (orbit-spherical `{target, azimuth, elevation, distance}`) and streams to the worker as a `setCameraPose` `RenderWorkerRequest` (DESIGN §Worker message protocol). **No gl-matrix** — the `@schema` readonly `Vec3` tuple already crosses store↔render and suits zustand's reference-equality (gl-matrix deferred to M4 per CLAUDE.md). Worker drives an **on-demand rAF loop** (`needsRender` dirty flag; synchronous-paint fallback under Node) replacing per-message `renderOnce`; a `readbackInFlight` guard protects the test-only readback. Pose drives the **perspective/volume camera only**, so it's inert on the default ortho slice until 4b + the volume toggle. Unblocks honest per-frame perf (M2.8 + exit gate) and the M2.13 HMR keep-pose prerequisite.
- [x] 4b. **Orbit/turntable controls + pointer input** — orbit/dolly/pan as **pure pose helpers** in `store/camera.ts` (`orbitPose`/`dollyPose`/`panPose`, fresh-object-per-call for `subscribeWithSelector`). `ui/pointerCamera.ts` (`ui → store` only) attaches pointer/wheel listeners to the main-thread `<canvas>` — `transferControlToOffscreen` moves only the drawing surface, so the element still gets DOM events — dispatching `setCameraPose` (`RenderWorkerRequest`); wired **guarded** so the headless test's fake canvas is untouched. Live HUD `ui/cameraChrome.ts`: bottom-left readout + a CSS-3D gnomon driven straight from the pose (no second renderer). Render side unchanged (4a's rAF loop coalesces a drag into one paint); inert-until-volume like 4a. **Deferred:** the `navMode` selector + free-trackball orbit (needs a quaternion pose), and the **projection toggle** (needs a matched-frustum ortho camera; rides the M2.5a compositor). **Follow-on (post-checkoff):** fly-through dolly (wheel past the near limit walks the pivot forward), camera **roll** (Shift+Q/E bank, Shift+R level — `roll` added to `CameraPose`/`DEFAULT_POSE`), **axis-snap hotkeys** (digits 1–6/0 jump to ±axis views), and a **help overlay** (`?`/`H`) backed by an authoritative `ui/shortcuts.ts` registry.
- [x] 5a. **Layer model** (instance-first foundation) — store `layers` registry: ordered `{id, kind: volume|slice|fieldlines|particles, inputs, colormapBindingId, visible, opacity, params}` + intents (add/remove/select/reorder/setVisible/setOpacity), in `store/layers.ts` (discriminated `Layer` union + pure list helpers). **Render worker composites the *visible* layers** into one scene (≤1-layer fast path = old `renderOnce`; ≥2 composite offscreen + present via a quad), replacing the single-`currentScene()` path — the retrofit you don't want to eat at M4. `recompute()` **auto-seeds one `volume` layer** (the only change-point) so the existing field-selector + window/level panel still drive it; per-layer opacity = a `uLayerOpacity` uniform. New `upsertLayer`/`removeLayer`/`setComposite` messages; `app/layerSync.ts` bridges store→worker (`computed` carries field data, `layers` carries structure). Renamed the mislabeled `layersPanel`→`colormapPanel`. **Deferred:** `ColormapBinding` + per-layer color/window → 5b; rail + Layers panel + per-layer settings + colorbar → M4; live N≥2 swapchain present + mixed-camera (world-space MPR) slices → M4.
- [x] 5b. **`ColormapBinding`** — the color-mapping a layer references (`layer.colormapBindingId`), webpic-native: `{id, field, colormap: ColormapId, window {center,width}, scale: linear|log|symlog}` in `@schema/colormap.ts` (the authority; the canonical `WindowLevel` moved here too). *Not* a mirror of magviz's bare-string prototype. Layers share or split bindings deliberately (slice + volume on one `|B|` binding, or distinct). Store gains a `colormapBindings` registry + `setBinding{Colormap,Window,Scale}` intents; `recompute()` seeds one binding and **retargets** it (field + full-range window; colormap/scale preserved) on field switch. **All three scales honored on the GPU** — `render/normalization.ts` is a uniform-selected TSL graph (in-shader log/symlog with ε-floors) with a pure-TS `windowedT` twin under analytic test. `app/layerSync.ts` adds a **bindings channel** for live colormap/window/scale; `colormapPanel.ts` drives the selected layer's binding. **Land before v0.1 freeze** so persisted-session round-trips don't break; `merge`/GC/the 2-colormap soft-warn + a magviz import adapter (`data/import/magviz.ts`) wait for the **M4 multi-layer UI** / M6.
- [x] 6. Min-max mipmap empty-space skipping — **gate contingency**, profiled then shipped **default-off**: it *regresses* the representative space-filling Gaussian flux-rope `|B|` (~24 ms vs ~13.5 ms — the skip-grid fetch + branch costs ~2× traffic for ~no skips). Built/tested/dormant: `render/minMaxGrid.ts` (per-brick min/max, **R32F + nearest** — Metal-safe: `float32-filterable` gates only *linear*) + `render/brickStep.ts` (TS twin of the WGSL brick-DDA); the `skipEmptySpace` path snaps skips back onto the fixed lattice so it's pixel-equal to the fixed march (GPU parity test). **Enable only for genuinely sparse data** (vacuum, isolated ropes); the gate stays open for space-filling `|B|` (needs step/resolution caps, LOD, or an M2 Pro re-run — see the exit gate).
- [x] 7. Gradient + Phong central-difference shading (~20 lines WGSL — shape-perception win) — a **per-layer toggle, off by default** for quantitative work (the lit "surface" is a TF-dependent opacity isosurface, not physical). 6 taps/step, so **gated on per-sample opacity AND a `uShade` uniform** — transparent samples skip the taps and default-off costs one uniform compare, leaving the gate's default path unchanged; `setShading()` flips it live (no rebuild, no re-upload). Central-difference gradient + two-sided headlight Blinn-Phong in `raymarchScene.ts`'s shared `accumulate` (lights both march paths); pure twin `render/shading.ts` under analytic test. `shaded: boolean` on the volume `Layer` + `setLayerShading` intent, threaded through `messages.ts`/worker/`layerSync` + a Phong checkbox in the colormap panel. **Render-local — *not* `coordinates/gradient`**; a shading normal isn't a physics operator.
- [x] 8. `timestamp-query` diagnostics panel (+ `performance.now` fallback) — the instrument for the exit gate + the M2.6 contingency call. **Deviation from "just wire `gpu/profiler.ts`":** that profiler times an *owned* compute pass and can't reach three's internal render encoder, so render-pass GPU time uses **three's built-in tracking** (`WebGPURenderer({trackTimestamp:true})` → `resolveTimestampsAsync('render')`); `gpu/profiler.ts` left untouched for M3 compute. New `render/frameTimer.ts` (two backends behind one iface); the worker posts a `frameTiming` `RenderWorkerResponse`, and `setContinuous` flips the on-demand loop to every-frame for sustained measurement. `ui/panels/diagnosticsPanel.ts`: rolling-mean readout vs the **8 ms gate**, honestly-labeled clock (timestamp-query vs "≈ wall-clock"). **Metal finding:** macOS render-pass timestamp-query advertises support but intermittently returns garbage durations, so the timer is **adaptive** — demotes to wall-clock for the session after 4 consecutive bad reads. **Follow-on:** feed the panel a 256³ volume to make the empty-space-skipping call (→ M2.6).
- [x] 9. **Time cursor + scrub control** — the prefetch prerequisite. Store gains `currentStep`/`availableSteps` + `setStep` (ignores an out-of-domain step, identity-skips a no-op) + a supporting `setAvailableSteps` (the reader→store seam: replaces the domain, snaps the cursor to the nearest survivor). `ui/panels/timePanel.ts` — a scrub `RangeControl` that walks **indices** into `availableSteps` (robust to sparse/non-contiguous steps), dispatches `setStep`, reflects external steps, disables on a 0/1-step domain. Registered as the `time` panel (`field → time → colormap → diagnostics`). **Cursor is inert pre-M2.10** — `setStep` updates the store but nothing re-reads yet (the streaming core wires that).
- [x] 10a. **Time-series streaming — data side** (the render-side ping-pong is 10b). Streaming is mandatory at 256³ (~64 MiB/field/step, ring depth N≈1–5, can't hold 256). A synthetic multi-step reader (`data/readers/synthetic.ts` — a time-varying Gaussian flux rope behind the `SimulationReader` protocol; step 0 ≡ `createSyntheticDataset` so the seed and streamed step 0 agree, no flash) gives the worker a real `openSimulation`/read/abort path. A pure, tested ring orchestrator (`data/stream.ts`) holds N decoded steps around the cursor, prefetches **±1** (index-space, sparse-robust), aborts in-flight reads the cursor scrubs past, evicts farthest-first, re-reads on scrub-back. The data worker reads + computes the scalar **off the main thread** (`computeField`) and transfers it straight to the render worker over a **paired `MessageChannel`** (protocol in `data/streamMessages.ts`, since `workers` can't import `render`). **Division that avoids double-sourcing:** `setStep` doesn't recompute, so `computed` is silent during a scrub → `layerSync` (initial + field-switch) and the data-worker stream (scrub) never fight.
- [x] 10b. **Time-series streaming — render side** — replace `swapLayerField`'s per-swap scene rebuild with an in-place **ping-pong `Data3DTexture`** double-buffer in `render/volumeTexture.ts` (`setField`): pack the new step into the inactive texture and swap the shared TSL node's value — a **bind-group swap, not a pipeline recompile**. The second buffer is allocated lazily on first swap; the CPU image is rewritten in place (no per-step 64 MiB realloc). `swapLayerField` does the in-place swap, **retains the live field** so a device-restore rebuild reproduces the on-screen step, and **falls back to a full rebuild** only when the scene declines (shape change, or a `skipEmptySpace` raymarch whose acceleration grid would go stale). Normalization stays the **binding's fixed window across steps** (no per-step autoscale flicker — the correct time-series behavior). Sustained 256³ scrub on base M2: p50 ≈ 22 ms (over the 8 ms gate — already open for space-filling `|B|` per M2.6, unchanged by 10b). **Deferred:** OPFS scrub-back caching (optional; the synthetic re-read is cheap + deterministic).
- [ ] 11. **Prefetch prediction `data/prefetch.ts`** — profile-then-tune, added only if the task-10 dumb ±1 stalls ("profile before tuning"). EWMA direction (window=8, α=0.7) + magnitude→count(1–5) + 250 ms debounce-on-flip + stationary→±1. Fuzz scrubber in `tests/prefetch.test.ts`.
- [ ] 12. **Eager pipeline compile** (production — gates the first-frame budget). `renderer.compileAsync(scene, camera)` (the renderer method — there is no `material.compileAsync`) warms the heavy raymarch pipeline *before its first `renderOnce`*, off the critical path, so the first frame doesn't hitch on driver compile. Not literally "at boot": `worker.ts:init()` only builds the triangle then; warm each heavy scene in `upsertLayer` (the volume/slice layer-build seam; coincides with boot only if a default dataset auto-loads). Post a compile-complete reply (a `RenderWorkerResponse` kind, DESIGN §Worker message protocol) so the UI can drop its spinner.
- [ ] 13. **Shader HMR** (dev-only — `import.meta.hot` is tree-shaken from prod). Edit WGSL/TSL in `raymarchScene.ts`, see it re-render **without a reload or losing state**. *Prerequisite:* camera pose must be **store-owned** (the `setCameraPose` `RenderWorkerRequest` kind, DESIGN §Worker message protocol) + an interactive camera must exist — today the camera is static and built *inside* `createRaymarchScene`, so a scene rebuild resets the very pose this promises to keep (built by M2.4a/4b). Mechanism: message-driven in-place rebuild (main watches the file → `rebuildShader` message → worker swaps the material), **preserving the `GPUDevice` + uploaded `Data3DTexture`** (don't re-upload 64 MiB per keystroke) and re-applying the stored pose — not vanilla worker `import.meta.hot`.
- [x] 14. **Package-split checkpoint** — **decided: stay single-package for v0.1** (DAG already enforced 3 ways; revisit at M6/embed, and if ever split, collapse math-y layers into one `@webpic/core` rather than promoting all 18). See `docs/DESIGN.md` §Package shape.
