## M3 — WebGPU compute + parity
Goal: GPU compute backend agreeing with pypic goldens. (WASM backend deferred → M9.)
- [x] 1. `compute/backends/webgpu` for `field.{magnitude,curl,divergence}` — built + proven vs the `coordinates/`+`derived/` twins on real M2 (headed Chrome). One standalone WGSL module (`shaders/kernels/{prelude,fieldOps}.wgsl.ts`, NOT TSL — rustpic-shareable) with three entry points sharing one bind layout + one `Params` struct; a thin recipe-agnostic `gpu/computeKernel.ts` runner (buffers → `pushErrorScope` → dispatch → copy-before-unmap readback → destroy-after-settle; no pipeline cache / no vramLedger for transient scratch). **Load-bearing decisions:** WGSL `diff1`+`axisStencil` are an exact mirror of `partialAlongAxis` (np.gradient edge_order=1; edge guarded *on the index* so no u32-underflow read); **1-D grid-stride loop** capped at the 65535-workgroup minimum so 256³ (16,777,216 > 65535·256) is covered by a 2nd pass; **std430 scalars-only `Params`** mirrored byte-for-byte by `params.ts`'s DataView (strides derived in-shader); inputs downcast f64→f32 (GPU output always `Float32Array`); curl `component` is a uniform `switch` (one pipeline); `div_e` free-bound to the field-agnostic divergence kernel. `supports()` = `hasDevice() && isWebgpuOp` — false in Node/worker — and the backend is **deliberately NOT in `field.ts`'s `BACKENDS`** (live routing needs a worker-reads/main-computes seam; a worker holds no `GPUDevice`). Tests: `webgpu.test.ts` (node — gating incl. the curl `component`/`needsGrid` regression guard, `Params` layout, downcast) + `parity.browser.test.ts` (gpu — smooth field, f32-into-both-sides, distinct-dims `[5,4,3]` + 256³ wraparound + non-cartesian throw) at `TOL.webgpu_f32` (rtol 1e-5/atol 1e-6, new row). **Deferred to M3.3:** TS-backend curl/div + the symmetric `ts`-vs-`webgpu` harness.
- [x] 2. `tests/tolerances.ts` — **per-kernel × per-precision** `{rtol,atol}` matrix (`TOL.<kernel>.<precision>`, bare operator keys: magnitude/divergence/curl/gradient × ts_f64/ts_f32/webgpu_f32/webgpu_f16), replacing the flat per-precision row. Each cell is **measured** where a test exercises it (mag/curl/div @ webgpu_f32 from M3.1; mag @ ts_f32; all @ ts_f64 linear-exact) or a **labeled derived** estimate (FD ts_f32; gradient webgpu — no WGSL kernel; **all webgpu_f16** — no f16 compute path in v0.1, `shader-f16` unrequested, paper bound from the f16 unit roundoff). The atol floor on curl/div/gradient is the honest knob for f32 cancellation at zero-crossings (magnitude needs none). `DEFAULT_TOLERANCE` (f64 floor) is the `assertAllclose` default; conservation + exact-zero tolerances stay inline (algebraic identity, not a precision gap). Structural guard `tests/tolerances.test.ts` (complete matrix; f64 tightest, f16 loosest; magnitude ≤ the FD ops). **Widen only with a measured reason** — M3.4 may widen curl/div ts_f64→~1e-10 + webgpu_f32 atol at 256³ on turbulent goldens.
- [x] 3. Cross-backend equivalence harness: `ts` vs `webgpu` per kernel — TS backend gains curl/divergence (`compute/backends/ts/operators.ts`, delegating to the one `coordinates/operators.ts` impl — never a duplicate) so the two backends bind the **same op set**; the op signature grew a `TsOpContext` (grid + component) the magnitude family ignores, `div_b`/`div_e` share one divergence op, and curl computes the full vector then selects `component` (covers `curl_B_*` + `vort_*`). `isTsComputable` now **mirrors `isWebgpuOp`** (dropped the needsGrid/component rejections — only gamma/c/species stay out of scope). **`computableFields` gained a grid-rank guard** (`gridCanEvaluate`: 3-D cartesian, ≥2 samples/axis) so the selector offers curl/div on real datasets (the synthetic n³ source) but never on a degenerate grid where the op would throw. **Harness:** backend-pair-parametrized `tests/crossBackend.ts` (`assertBackendsAgree` + `CROSS_BACKEND_CASES`) compares **data within the per-kernel `webgpu_f32` cell AND metadata exactly** (shape/units/latex/reduction/quantityType) — proving the full `ComputeBackend` path agrees, not just the raw kernels; M9's WASM backend reuses it. The smooth analytic field moved to a shared `tests/analyticField.ts` (consumed by the new `crossBackend.browser.test.ts` *and* the refactored `parity.browser.test.ts` — one fixture, not two); f32 fed to both sides so only the f32-vs-f64 arithmetic gap remains.
